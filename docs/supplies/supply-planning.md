# Планирование поставок

«Планирование поставок» — отчёт-калькулятор: на одном экране вы видите все свои товары, все склады Ozon, текущие остатки и расход, и сразу — **сколько товара куда нужно довезти**, чтобы покрыть будущий спрос. Без этого инструмента продавцы либо постоянно «уходят в ноль» по запасу (и теряют продажи), либо завозят слишком много (и платят за хранение).

Отчёт устроен необычно: товары в строках, **кластеры (региональные группы складов) — в колонках**. По каждому пересечению видно: остаток, ожидаемый расход, рекомендуемая поставка. Дополнительно — десятки фильтров и параметров, чтобы подстроить расчёт под вашу бизнес-логику: сезонность, кратность упаковки, режим работы со складами.

Этот раздел проводит по всем возможностям отчёта.

---

## 1. Где найти и общий вид

1. Откройте **Поставки → Планирование**.
2. В шапке выберите магазин.
3. Откроется таблица: товары слева, кластеры по горизонтали.

В шапке отчёта:

- **Параметры расчёта** — период потребности, период анализа заказов, прирост.
- **Чипы статусов запаса** — для быстрой фильтрации проблемных и избыточных позиций.
- **Чипы категорий** — фильтр по типам товаров.
- **Поиск, избранное, фильтр наличия** — дополнительные инструменты.
- **Управление кластерами и колонками** — настройка вида таблицы.
- **Действия** — заполнить подсорт, очистить, скачать сборочный лист, импорт/экспорт.

---

## 2. Параметры расчёта потребности

В верхней части toolbar три ключевых параметра, которые определяют **что считается потребностью**:

- **Период потребности** (по умолчанию 30 дней) — на сколько дней вперёд планируем запас.
- **Период анализа заказов** (по умолчанию 30 дней) — за сколько прошлых дней брать среднюю скорость продаж.
- **Прирост заказов** (по умолчанию 0%) — ожидаемый рост или падение спроса. Например, +50% перед сезоном, −30% при выходе из сезона.

Формула расчёта:

```
Среднесуточные заказы × (1 + прирост%) × Период потребности
− (текущие остатки + товары в пути + возвраты + товары на поставке)
= Рекомендуемый подсорт
```

Дополнительно есть два чекбокса:

- **«На поставке»** — учитывать ли товары, которые вы уже включили в черновики поставок.
- **«Мои остатки»** — ограничивать ли подсорт вашими собственными запасами на складе. Если включено и ваши остатки меньше потребности — подсорт ограничивается тем, что у вас реально есть.

!!! tip "Подсказка"
    Прирост — самое мощное и часто забытое поле. Стандартный расчёт берёт прошлые 30 дней как базу. Если впереди новогодний пик или сезон, реальная потребность будет в 2–3 раза выше — поставьте прирост +100% или +200%. Иначе придёте на пик с пустыми складами.

---

## 3. Чипы статусов запаса

Над таблицей — четыре чипа с **счётчиками** SKU в каждом статусе:

| Чип | Дней запаса | Что значит |
|---|---|---|
| 🔴 **Дефицит** | ≤ 7 дней | Товар закончится в ближайшие 7 дней. Срочно везти. |
| 🟡 **Внимание** | 8–14 дней | Запас тает. Поставку нужно начать в ближайшие дни. |
| 🟢 **Норма** | 15–60 дней | Всё в порядке, можно заняться позже. |
| ⚫ **Избыток** | > 60 дней | Товара слишком много. Хранение растёт, оборачиваемость падает. |

Один клик по чипу = фильтр таблицы по этому статусу. Можно выбрать несколько одновременно.

!!! tip "Подсказка"
    Стандартный утренний обход поставок: открыли «Дефицит» → если есть SKU, сразу формируете подсорт. Открыли «Избыток» → решаете, что с ним делать (акция, снижение цены, снять с продаж).

---

## 4. Фильтры

Помимо статусов, есть ещё несколько фильтров:

### Категории

Чипы по типам товаров (категориям Ozon). При большом количестве категорий лишние сворачиваются под кнопку «Ещё +N». Один клик = фильтр.

### Поиск

Поле поиска принимает offer_id или часть названия. Фильтрует таблицу мгновенно.

### Избранное

Кнопка со звёздочкой. После активации в таблице остаются только избранные товары. Сами избранные настраиваются через отдельный модальный диалог — туда заносите SKU, по которым хотите следить особо внимательно (свои топ-продавцы, новинки, сезонные хиты).

### Фильтр по наличию

Чип с четырьмя режимами:

- **Все** — показывать все товары.
- **С остатками** — только те, у кого есть остаток.
- **С заказами** — только те, у кого были заказы за период.
- **Остатки + Заказы** — только активные товары (есть и остаток, и продажи).

Удобно отсечь «мёртвые» SKU без заказов и без остатков, чтобы сосредоточиться на работающем ассортименте.

---

## 5. Структура таблицы

Каждая строка — товар. Колонки делятся на две части:

### Левая часть (закреплена)

- **Карточка товара** — фото, offer_id, название.
- **Категория**, **модель** (если назначена), **бренд**.
- **Дни запаса** — главная метрика статуса: за сколько дней закончится при текущих темпах.
- **Среднесуточные заказы** — сколько в среднем продаётся за день.
- **Кратность упаковки** — сколько штук в одной коробке (если настроено).
- **Подсорт итого** — суммарный рекомендуемый завоз по всем складам.

### Правая часть — кластеры

Каждый кластер (Москва, СПб, Восток, Сибирь и т.д.) — это группа складов в регионе. Под каждым кластером 6–8 подколонок с детальной информацией:

- **Доступно** — сколько товара сейчас на складах кластера.
- **В пути** — сколько уже едет к этому кластеру.
- **Заказано** — продажи через этот кластер за период анализа.
- **Возвраты** — возвратов за период.
- **Потребность** — расчётное количество для покрытия будущего спроса.
- **Подсорт** — рекомендуемая поставка (можно редактировать вручную).

---

## 6. Управление кластерами

У продавца на FBO Ozon обычно 5–15 кластеров. Все одновременно показывать неудобно — поэтому есть гибкое управление.

### Попап выбора кластеров

Кнопка **«Кластеры»** открывает попап с:

- **Чекбоксами** для каждого кластера (показать / скрыть).
- **Сортировка**: А-Я / по остаткам убыв. / по заказам убыв.
- **Быстрый фильтр**: все / только с остатками / только с заказами.

### Индивидуальные настройки кластера

В каждом кластере есть иконка **[⋯]** — открывает настройки именно этого кластера:

- Свой период потребности (если, например, на склад Москвы возите за 30 дней, а на Хабаровск — за 60 из-за длинной логистики).
- Свой прирост заказов.
- Учёт нелокальных заказов.

Индивидуальные настройки имеют приоритет над общими.

!!! tip "Подсказка"
    Если у вас есть один кластер, продажи в котором сильно отличаются (например, активный Восток или, наоборот, тихий Юг) — задайте ему свой прирост. Общие настройки на всю таблицу часто дают перекос: либо везёте мало туда, где надо много, либо лишку туда, где нужно немного.

---

## 7. Управление подколонками

В каждом кластере 6–8 подколонок (Доступно, Заказано, Подсорт и т.д.). Если вам нужно только 2–3 — лишние можно скрыть:

- **Кнопка «Колонки»** или иконка фильтра в шапке кластера → попап с чекбоксами подколонок.
- Скрытое восстанавливается тем же путём.

Между видимыми и скрытыми появляется **маркер `+N`** — клик по нему быстро восстанавливает группу.

---

## 8. Подсорт — главное действие

Колонка **«Подсорт»** в каждом кластере — это **то, что вы планируете отгрузить**. Основной рабочий цикл:

### Заполнить автоматически

Кнопка **«Заполнить подсорт»** в toolbar — рассчитает рекомендуемые значения для всех видимых строк (и видимых кластеров) на основе формулы потребности.

Если включена **кратность упаковки**, значения округлятся до ближайшей коробки вверх.

### Ручная корректировка

Любую ячейку «Подсорт» можно отредактировать вручную: кликните, введите своё число. Это переопределит автоматическую рекомендацию.

Полезно, если знаете больше, чем формула: «На этом складе обычно проблемы с приёмкой, повезу меньше», «Этот товар в эту неделю на акции, нужно больше».

### Очистить

Кнопка **«Очистить подсорт»** — обнуляет все значения подсорта в таблице. Удобно, если хотите начать заполнение с нуля.

---

## 9. Сборочный лист и импорт/экспорт

Когда подсорт заполнен — формируется итоговая поставка:

### Сборочный лист

Кнопка **«Сборочный лист»** — выгружает архив XLSX-файлов:

- Отдельный файл для каждого склада / кластера.
- Структура соответствует требованиям Ozon — можно использовать как готовый шаблон при оформлении поставки в кабинете Ozon Seller.

Кнопка активна только если подсорт где-то заполнен (хотя бы одна ненулевая ячейка).

### Экспорт XLSX

Кнопка экспорта выгружает текущий план целиком в XLSX. Удобно для бухгалтерии, для согласования с поставщиком или для своих расчётов в Excel.

### Импорт XLSX

Кнопка импорта позволяет загрузить план из файла:

- Скачайте **шаблон** через ссылку в попапе импорта.
- Заполните в Excel (часто удобнее, чем редактировать в браузере).
- Загрузите обратно. Система разнесёт значения по складам и кластерам.

## 10. Что сохраняется в браузере

Планирование запоминает все настройки:

- Период потребности и анализа заказов
- Прирост, чекбоксы «На поставке» / «Мои остатки»
- Активные фильтры (статусы, категории, наличие, поиск, избранное)
- Видимость кластеров и подколонок, сортировка кластеров
- Индивидуальные настройки каждого кластера

При следующем открытии всё на месте.

## 11. Сценарии использования

### Утренний обход (10 минут)

1. Откройте «Планирование».
2. Кликните чип **«Дефицит»** — увидите критичные позиции.
3. Кликните **«Заполнить подсорт»** — система рассчитает рекомендации.
4. Скачайте **«Сборочный лист»** — заводите поставку в Ozon.

### Подготовка к сезону (30 минут раз в месяц)

1. Поставьте **прирост заказов** на +100% (или сколько ожидаете).
2. Период потребности — 60 дней (с запасом).
3. Заполните подсорт, проверьте кластеры, при необходимости скорректируйте.
4. Сборочный лист → распределение на 2–3 поставки.

### Чистка избытков

1. Кликните чип **«Избыток»** — увидите SKU с запасом >60 дней.
2. По каждому: либо снизить цену в Ozon, либо запустить акцию, либо снять с продаж и продавать остатки до конца.
3. Подсорт по этим товарам не заполняем — везти больше не надо.

### Анализ конкретного региона

1. Через попап «Кластеры» оставьте только нужный (например, «Восток»).
2. Скрытие остальных делает таблицу компактной.
3. Видите, что и сколько там продаётся, и куда нужны поставки.

### Загрузка плана из Excel

1. Скачайте шаблон через импорт.
2. Заполните в удобной программе (1С, Excel, Google Sheets).
3. Загрузите обратно — план применится за 1–2 минуты.

!!! example "Пример расчёта"
    Свитер мужской, средние продажи 10 шт/день. Впереди декабрь — пик +100%. На складе Москвы:

    - **Среднесуточные заказы:** 10 × 2.0 (прирост) = 20 шт/день
    - **Период потребности:** 30 дней → нужно 600 шт
    - **Доступно сейчас:** 150 шт
    - **В пути:** 50 шт
    - **Потребность:** 600 − 150 − 50 = **400 шт**
    - **Кратность упаковки** = 12 → **408 шт** (34 коробки)

    Вот эту цифру 408 система покажет в столбце «Подсорт» для кластера Москвы. Дальше вы либо принимаете её, либо корректируете.

## 12. Что важно помнить

!!! warning "Важно"
    Планирование — **рекомендательный** инструмент. Финальное решение по объёму поставки всегда за вами. Если знаете о факторах, которые формула не учитывает (грядущая акция, акт диверсификации, проблемы со стороной поставщика) — корректируйте подсорт вручную.

!!! tip "Подсказка"
    Не везите весь ассортимент одной поставкой на один склад. Делайте сборные поставки на 2–3 склада параллельно — снижает риски при сбое приёмки и улучшает географию для покупателей. Лучше две средние поставки в месяц, чем одна большая.

!!! warning "Важно"
    Расчёт «дней запаса» считается по **средней скорости за прошлые 30 дней**. Если у вас сильный рост (новый магазин, разгон рекламы), сильное падение или ярко выраженная сезонность — средняя за 30 дней не отражает реальной динамики. Делайте поправку через прирост.

## Частые ошибки

- **Не учтена кратность упаковки** — рекомендация «довезти 35 штук», а товар отгружается коробками по 12. Включите кратность — система округлит до ближайшей коробки.
- **Используются общие настройки вместо индивидуальных** — у одного кластера продажи 5 шт/день, у другого 25 шт/день. Если задать общий период «30 дней» — везде везёте одинаково неправильно. Задавайте кластерам индивидуальные параметры.
- **Не учитывают сезонность** — расчёт строится на прошлых 30 днях. Если впереди пик — реальная потребность будет в 2–3 раза выше. Применяйте свой прирост.
- **Игнорируют чип «Избыток»** — у одного товара 5 дней запаса, у другого 250. Берут только первый, а второй продолжает копиться, хранение растёт.
- **Везут весь ассортимент на один склад** — выгодно по логистике, но рискованно: при сбое приёмки на этом складе продажи остановятся целиком.
- **Заполнили подсорт автоматически и не проверили вручную** — формула не знает про ваши планы (акция, новинка, эксперимент). После авто-заполнения пробегите глазами, особенно по самым крупным значениям.
- **Не используют избранное** — следить за всем магазином через вкладку каждый день тяжело. Заведите избранное на топ-30 SKU, проверяйте их в первую очередь.

## Частые вопросы

**Откуда STPulse знает мои остатки?**
Из импорта данных Ozon — раздел «Мои остатки» обновляется при ежедневной синхронизации. Если вы добавили новую партию или сделали отгрузку — изменения отразятся через 1 сутки.

**Что такое «нелокальные заказы» и зачем их учитывать?**
Это заказы, отгруженные не с ближайшего склада, а с дальнего (когда на ближайшем товара не было). Если их не учитывать, расчёт потребности будет занижен — мы не заметим спрос в регионе. Стандартно лучше учитывать.

**Сколько дней потребности оптимально планировать?**
30 дней — стандартный вариант. Если у вас длинный цикл поставок (товар идёт от поставщика 30+ дней), считайте на 60. Если короткий и есть склад в наличии — можно на 14. Главное правило: **период потребности > времени поставки**.

**Что делать, если рекомендации по подсорту кажутся завышенными?**
Сначала проверьте: учтены ли товары «в пути»? Включён ли учёт «На поставке»? Включена ли «Мои остатки» (если у вас узкое место в собственном запасе)? Если всё в порядке, но рекомендация всё равно кажется большой — возможно, формула права, и вы просто переоценили свой запас.

**Как сформировать поставку по нескольким SKU сразу?**
Кнопка «Сборочный лист» создаёт XLSX со всеми артикулами, для которых заполнен подсорт. Распределение по складам уже учтено. Этот файл — готовый шаблон для оформления поставки в кабинете Ozon.

**Можно ли загрузить готовый план из Excel вместо ручного заполнения?**
Да. Кнопка импорта → скачайте шаблон → заполните в Excel/1С → загрузите обратно. Удобно, если у вас уже есть планирование в другой системе.

**Что значит «Мои остатки» в настройках?**
Это переключатель: если у вас ограниченный запас собственного товара (на своём складе или у поставщика), включите чекбокс. Тогда подсорт никогда не превысит ваши реальные остатки. Без этой галки система может рекомендовать завезти больше, чем у вас физически есть.

**Можно ли добавить кластер вручную, если я работаю с FBS?**
Нет, кластеры берутся из Ozon (это официальная региональная сегментация площадки). Для FBS-склада планирование тоже работает, но кластеры всё равно — Ozon-овские.

**Подсорт «Очистить» удаляет данные навсегда?**
Очищает только текущие значения в таблице, не сами товары. После очистки можно снова нажать «Заполнить» — пересчитает с нуля.

**Зачем избранное, если есть фильтры?**
Избранное — это ваш личный список «следить особо». Например, у вас 1000 SKU, но 30 из них — топ-продавцы или сезонные хиты, у которых нельзя допустить дефицита. Включаете «Избранное» — видите только их, без шума.

---

Планирование поставок — это про **баланс**. Слишком мало товара — потеряете продажи и место в выдаче. Слишком много — потеряете деньги на хранении. STPulse не принимает решение за вас, но даёт точные числа для решения. Если делать недельную/двухнедельную ревизию по 30 минут — у вас никогда не будет дефицита, а излишки на складе сократятся в 2–3 раза.
